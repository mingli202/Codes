The Image Library🔗

1.1 Images🔗

The Imagelib library provides a number of basic image classes, along with combinators for building more complex images out of existing images. Basic images include various polygons, ellipses and circles, and text, as well as bitmaps. Existing images can be rotated, scaled, flipped, and overlaid on top of each other.

(In fact, the background is drawn 1 pixel larger in each direction, so that any outlines or edges are more clearly seen.)

Note: All images in this tutorial are drawn on a light-gray background, so that it’s apparent what the extent of the image actually is. This means that images drawn as outlines, for example, will appear to be filled with light-gray. To produce exactly the images seen here, you’ll need to overlay them onto a gray rectangle yourself.

Note: Many image constructors come in two signatures, one taking a Color value and one taking a string describing the name of the color. When using the string color-name form, valid color names are defined here, including the color "transparent". The image library treats color names case-insensitively, and ignores spaces and dashes in the name. For instance, "LightYellow", "lIgHtYeLlOw", "light yellow" and "light-yellow" all name the same color.

1.1.1 Basic image properties🔗

Every image has a width and height, that can be obtained via the Width and Height properties.

Every image also has a bounding box, obtained by the BoundingBox property, representing the top-left and bottom-right corners of the image, in that image’s own coordinate system, which is a Cartesian system whose whose y-axis points down. No guarantee is given that the origin of the coordinate system is at the center of the image, or at the top-left corner of the image. This should have no observable consequences for any of the image constructions described below.

Finally, every image has a pinhole, described further below.

1.1.4 Overlaying Images🔗

  • new OverlayImage(WorldImage top, WorldImage bot)
    Arguments:

    • WorldImage top:   the top image for the combined image

    • WorldImage bot:   the bottom image for the combined image

Constructs a combined image with top image overlaid over the bottom image. The top image will be placed such that its pinhole aligns with the bottom image’s pinhole. For more information about pinholes, see Pinholes. 

new OverlayImage(new RectangleImage(30, 60, OutlineMode.Fill, Colors.Green),
                 new EllipseImage(60, 30, OutlineMode.Fill, Colors.Purple))

  • new OverlayOffsetImage(WorldImage top, double dx, double dy, WorldImage bot)
    Arguments:

    • WorldImage top:   the top image for the combined image

    • double dx:   Amount to shift the bottom image along the X axis

    • double dy:   Amount to shift the bottom image along the Y axis

    • WorldImage bot:   the bottom image for the combined image

Constructs a combined image with top image overlaid over the bottom image. The top image will be placed such that its pinhole aligns with the bottom image’s pinhole. For more information about pinholes, see Pinholes. The bottom image will then be offset by dx and dy.

1.1.6 Bitmaps and Manipulating Individual Pixels🔗

  • new FromFileImage(string fileName)
    Arguments:

    • string fileName:   The file name of the image source

Constructs an image from a source jpg or png. Relative paths are resolved according to the current working directory of the running program.

Note: To use image files in your project, and have them be available in the build directory, the easiest approach is to mark the image files as “Content” in your .csproj file, as follows:

<ItemGroup>

  <Folder Include="images\" />

</ItemGroup>

 

<ItemGroup>

  <None Remove="images\*.png" />

  <Content Include="images\*.png">

    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>

  </Content>

</ItemGroup>

This instructs the build process to copy all the .png files in your images\ subdirectory across into the build\ directory at the same relative paths as they are in your source code. Then you can refer to new FromFileImage("images/yourImage.png") and have it work at runtime.

  • new FrozenImage(WorldImage img)
    Arguments:

    • WorldImage img:   The image to freeze

Freezing an image internally builds a bitmap, draws the image into the bitmap and then uses the bitmap to draw that image afterwards. Typically this is used as a performance hint. When an image both contains many sub-images and is going to be drawn many times, freezing the image can substantially improve performance without changing how the image draws.

  • new ComputedPixelImage(int width, int height)
    Arguments:

    • int height:   The height of the image

A ComputedPixelImage is intended to allow you to mutably compute the contents of an image, one pixel at a time. The constructor for this class creates an empty (i.e., completely transparent) image of the desired width and height. To manipulate the image, you use the following methods:

    • Point point:   The coordinates of the pixel

    • string c:   The name of the desired new color of the pixel

Sets the requested pixel to the provided Color, or throws an ArgumentOutOfRangeException if the provided coordinates are not within the bounds of the picture. Both method names are provided, and they do the same thing.

  • void SetPixels(int x, int y, int width, int height, Color c)
    Arguments:

    • int x:   The column of the pixel

    • int y:   The row of the pixel

    • int width:   The width of the pixel block

    • int height:   The height of the pixel block

    • Color c:   The desired new color of the pixels

  • void SetPixels(int x, int y, int width, int height, string c)
    Arguments:

    • int x:   The column of the pixel

    • int y:   The row of the pixel

    • int width:   The width of the pixel block

    • int height:   The height of the pixel block

    • string c:   The name of the desired new color of the pixels

Sets a rectangular block of pixels, with the top left corner specified by (x,y) and with the given width and height, to the provided color. If any of the requested pixels are out of range, throws an ArgumentOutOfRangeException exception.

The GetColorAt method can also be used with FromFileImages, FrozenImages and WorldCanvases, to get the colors of individual pixels there. For example, you could load a FromFileImage, create a ComputedPixelImage of the same size, and then loop over all the pixels in the file image to produce a new image that transforms each of the colors in some way (e.g., brightening or darkening them).

1.1.7 Saving images🔗

You can save WorldImages or WorldScenes to a PNG file:

  • bool SaveImage(string fileName)
    Arguments:

    • string fileName:   The name of the file to save.

This method will produce a PNG image file that’s the same size as the image or scene. (For images, the file will be exactly as large as the image; for scenes, it will be the size of the scene regardless of what’s being drawn.) The return value is true if the file was successfully saved. Relative paths are resolved according to the current working directory of the running program.

1.1.8 Pinholes🔗

Pinholes are used as guidepoints for overlaying images. OverlayImage will align each image’s pinhole, and OverlayOffsetAlignImage can be specified to align along pinholes. The pinhole can be moved using one of the following methods:

  • WorldImage CenterPinhole()

  • WorldImage MovePinhole(double dx, double dy)
    Arguments:

    • double dx:   The offset to shift the pinhole rightward

    • double dy:   The offset to shift the pinhole downward

  • WorldImage MovePinholeTo(Point newPinhole)
    Arguments:

    • Point newPinhole:   The new pinhole coordinates, relative to the top-left corner of the image

  • WorldImage MovePinholeTo(Point newPinhole, AlignMode anchor)
    Arguments:

    • Point newPinhole:   The new pinhole coordinates, relative to the specified anchor of the image

    • AlignMode anchor:   An anchor point within the image, relative to which the pinhole is computed

CenterPinhole creates a new image from an existing image, whose pinhole is at the center of its bounding box.

MovePinhole creates a new image from an existing image, that offsets the existing pinhole by the requested amount.

MovePinholeTo creates a new image from an existing image and replaces its pinhole with the specified coordinates. By default, these coordinates are measured from the top-left of the image, but you can specify an alternate anchor instead, that describes one of ten locations within the image:

  • AlignMode.Pinhole

  • AlignMode.TopLeft

  • AlignMode.TopCenter

  • AlignMode.TopRight

  • AlignMode.CenterLeft

  • AlignMode.Center

  • AlignMode.CenterRight

  • AlignMode.BottomLeft

  • AlignMode.BottomCenter

  • AlignMode.BottomRight

All four methods will create a new image with the moved pinhole; the original image is unchanged.

  • new VisiblePinholeImage(WorldImage img)
    Arguments:

    • WorldImage img:   The image to overlay the pinhole representation

  • new VisiblePinholeImage(WorldImage img, Color color)
    Arguments:

    • WorldImage img:   The image to overlay the pinhole representation

    • Color color:   The color to draw the pinhole mark

  • new VisiblePinholeImage(WorldImage img, string color)
    Arguments:

    • WorldImage img:   The image to overlay the pinhole representation

    • string color:   The name of the color to draw the pinhole mark

This constructs an image that overlays a cross over the pinhole of the img. The resulting image has its pinhole in the same place, and is the same size as the underlying image, so that one can easily add or remove visible pinholes while debugging how images are drawn. By default, the pinhole is drawn in black, but you may specify an alternate color. 

new CircleImage(30, OutlineMode.Outline, Colors.Red)
new VisiblePinholeImage(new CircleImage(30, OutlineMode.Outline, Colors.Red))
new VisiblePinholeImage(new CircleImage(30, OutlineMode.Outline, Colors.Red).MovePinhole(10, 10))
new VisiblePinholeImage(new CircleImage(30, OutlineMode.Outline, Colors.Red).MovePinhole(10, 10), Colors.Blue)

By default, pinholes are placed at the visual center of most images. For most images, this is the same as their physical center, but for polygons and stars with odd numbers of corners, the two positions are different: 

new VisiblePinholeImage(new RegularPolyImage(30, 3, OutlineMode.Outline, Colors.Red), Colors.Blue)
new VisiblePinholeImage(new RegularPolyImage(30, 3, OutlineMode.Outline, Colors.Red).CenterPinhole(), Colors.Black)

This placement makes the pinhole coincide with the center of the circle surrounding the polygon, rather than the center of its bounding box, so that rotating the polygon looks smooth rather than lopsided: 

WorldImage triUp = new EquilateralTriangleImage(30, OutlineMode.Outline, Colors.Red);
WorldImage triDown = new RotateImage(new EquilateralTriangleImage(30, OutlineMode.Outline, Colors.Blue), 180);
new OverlayOffsetAlignImage(AlignModeX.Center, AlignModeY.Middle, triUp, 0, 0, triDown)

WorldImage triUp = new EquilateralTriangleImage(30, OutlineMode.Outline, Colors.Red);
WorldImage triDown = new RotateImage(new EquilateralTriangleImage(30, OutlineMode.Outline, Colors.Blue), 180);
new OverlayOffsetAlignImage(AlignModeX.Pinhole, AlignModeY.Pinhole, triUp, 0, 0, triDown)

Note that pinholes do not affect the bounding box of an image. In particular, if two images have pinholes outside their bounding boxes, and are placed beside each other, this may look confusing: 

WorldImage blueRect = new RectangleImage(30, 40, OutlineMode.Fill, Colors.Blue).MovePinhole(30, 40)
new VisiblePinholeImage(blueRect, Colors.Blue)

WorldImage redRect = new RectangleImage(30, 40, OutlineMode.Fill, Colors.Red).MovePinhole(-30, 40)
new VisiblePinholeImage(redRect, Colors.Red)

new VisiblePinholeImage(new BesideImage(redRect, blueRect), Colors.Yellow)

There is no space between the two rectangles, despite where the pinholes are, and the resulting image’s pinhole is in the center of the image.

1.2 WorldScenes🔗

  • new WorldScene(int width, int height)
    Arguments:

    • int width:   The width of the scene

    • int height:   The height of the scene

A WorldScene is a canvas on which to draw WorldImages. It is used by Worlds to be drawn on each tick. WorldScene supports only a single method:

  • WorldScene PlaceImageXY(WorldImage img, double x, double y)
    Arguments:

    • WorldImage img:   the image to be drawn

    • double x:   the x-coordinate to place the image at

    • double y:   the y-coordinate to place the image at

  • WorldScene PlaceImageXY(WorldImage img, AlignMode anchor, double x, double y)
    Arguments:

    • WorldImage img:   the image to be drawn

    • AlignMode anchor:   the anchor point of the image to be used

    • double x:   the x-coordinate to place the image at

    • double y:   the y-coordinate to place the image at

This method places the given image with its pinhole on the specified coordinates, and returns the new enhanced scene. Parts of the image that extend beyond the scene boundaries will be cropped.

Use this method in sequence to place multiple images on a scene: 

new WorldScene(width, height)
    .PlaceImageXY(image1, x1, y2)
    .PlaceImageXY(image2, x2, y2)
    ...
    .PlaceImageXY(imageN, xN, yN)

Or, build up a composite image (using any of the image constructions above) and place everything on the scene at once.

The second overload is very similar to the one above, but allows specifying an anchor point of the image that should be placed at the desired coordinates. The possible anchor points are the same as for MovePinholeTo above.

Note: See also Funworld versus Impworld below.

1.2.1 Scenes from images🔗

  • WorldScene WorldScene.FromImage(WorldImage img)
    Arguments:

    • WorldImage img:   the image to be drawn

This helper method allows creating a new WorldScene that contains just the given image as its contents.

Note: See also Funworld versus Impworld below.

1.2.2 Displaying scenes with WorldCanvas🔗

In order to render an image on-screen, we need to create a window in which to display it. A window is not the same thing as a scene, much as a canvas is not the same thing as a painting. Accordingly, the image library defines a WorldCanvas class, onto which we can draw a scene and then show the canvas: 

new WorldCanvas() // create the canvas onto which we can draw a scene
    .DrawScene(ourScene)  // actually paint the scene onto the canvas
    .Show()       // display our artistic masterpiece to the end-user

The window shown will be the same size as the scene being drawn. The method returns a boolean value, which will be true whenever the image is successfully displayed.

1.3 Worlds🔗

  • new World()

World is an abstract class that must be extended to implement any particular game. The only method that must be overridden is MakeScene; other methods may be overridden if needed.

1.3.1 MakeScene🔗

WorldScene MakeScene()

This method must return the WorldScene to be shown on each clock tick.

1.3.2 BigBang🔗 

bool BigBang(int width, int height, double secondsPerTick)

Invoke BigBang on a World, passing in the intended width and height of the window to be opened. (This may be distinct from the size of the WorldScene being displayed; if so, the scene will be drawn in the upper-left corner of the window.)

Additionally, pass in a double representing the speed (in seconds) of the tick-rate. Only positive numbers will work; zero or negative numbers will be ignored and the clock will not tick.

As a convenience, merely to test that your code compiles and can display anything, BigBang is overridden to take just a width and height, and assumes a clock speed of zero.

Note: If you intend to specify an ending for the world, then your clock rate matters. If your clock rate is zero and therefore the clock does not tick, then you must use the EndOfWorld method for ending the world, rather than the WorldEnds method; see Ending the World below.

To kick off your program, you will likely write a simple test method that just invokes BigBang. It doesn’t actually call any test methods on the given Tester object, but it’s enough for the tester library to find and run for you: 

class ExamplesMyWorldProgram {
  bool testBigBang(Tester t) {
    MyWorld w = ... however you create your world ...
    int worldWidth = ...however wide you want the window to be...
    int worldHeight = ...however tall you want the window to be...
    double tickRate = ...however fast you want the tick rate to be (in seconds/frame)...
    return w.BigBang(worldWidth, worldHeight, tickRate);
  }
}

1.3.3 GetBlankScene🔗

WorldScene GetBlankScene()

This convenience method will return an empty scene sized to fit the current window. This may be easier to use than keeping the sizes of the window and the scene in synch in multiple places in your code.

1.3.4 Handlers🔗

There are several handlers you can override to provide behavior for your game:

  • OnTick() handles ticking the clock and updating the world.

  • OnKeyDown(string key) handles key input and is given the key that has been pressed.

  • OnKeyUp(string key) handles key released and is given the key that has been released.

  • OnMouseEntered, OnMouseExited, OnMouseMoved, OnMousePressed and OnMouseReleased handle the common behaviors of a mouse, and are described below.

You will almost always override OnTick, and will likely override OnKeyDown and/or OnMousePressed.

1.3.4.1 Key handlers🔗

Both the OnKeyDown and OnKeyUp events receive a key name describing the key that has been pressed or released. Key events may happen repeatedly, if the key is pressed and held down and that key isn’t just a modifier key (like Shift or Control).

Most keys are described as themselves: e.g., pressing the A key will result in the key "a" being sent; likewise pressing the Z key will result in the key "z" being sent. Typing @ by pressing the shift key, then 2, then releasing the shift key, then releasing 2, will generate several key events:

  • A key down of "LeftShift" or "RightShift"

  • A key down of "@"

  • A key up of "LeftShift" or "RightShift"

  • A key up of "2"

If keys appear in both left and right forms (e.g. the shift keys), then they will be named "LeftShift" and "RightShift", "LeftControl" and "RightControl" etc. If keys appear both on the normal keyboard and the number pad, they will be named "0" and "Num0", etc.

The following keys are given special descriptive names:

  • "Enter"

  • "Backspace"

  • "Tab"

  • "Insert"

  • "Home"

  • "PageUp"

  • "PageDown"

  • "Delete"

  • "End"

  • "NumLock"

  • "ScrollLock"

  • "CapsLock"

  • "Escape"

  • "ContextMenu"

  • "F1"

  • "F2"

  • "F3"

  • "F4"

  • "F5"

  • "F6"

  • "F7"

  • "F8"

  • "F9"

  • "F10"

  • "F11"

  • "F12"

  • "Up"

  • "Down"

  • "Left"

  • "Right"

1.3.4.2 Mouse handlers🔗

There are five distinct mouse events:

  • OnMousePressed(Point pos) – when a mouse button is pressed

  • OnMouseMoved(Point pos) – when the mouse cursor is moved

  • OnMouseReleased(Point pos) – when a mouse button is released

  • OnMouseEntered(Point pos) – when a mouse is moved to enter the window

  • OnMouseExited(Point pos) – when a mouse is moved to exit the window

For each of these events, the Point gives the coordinates of the mouse cursor, relative to the contents of the window.

If you need to detect which mouse button is being clicked, pressed or released, or held while moving, there are additional overloaded methods:

  • OnMousePressed(Point pos, string buttonName) – when a mouse button is pressed, and which button is pressed

  • OnMouseMoved(Point pos, string buttonName) – when the mouse cursor is moved, and which button is pressed

  • OnMouseReleased(Point pos, string buttonName) – when a mouse button is released, and which button is released

  • OnMouseEntered(Point pos, string buttonName) – when a mouse is moved to enter the window, and which button is pressed

  • OnMouseExited(Point pos, string buttonNAme) – when a mouse is moved to exit the window, and which button is pressed

The buttonName argument will be one of "Left", "Middle" or "Right".

Note: You should not override both versions (with and without the string argument) of any of these methods. If you need the mouse button, override these versions; if you do not care about buttons, use the simpler forms above.

1.3.5 Ending the World🔗

When the game is over, you have two mechanisms for signaling the end of the world. The first of these two methods can be used no matter how your world program is running; the second can only be used when you have a clock that ticks.

1.3.5.1 EndOfWorld and LastScene🔗

The easier alternative is to return this.EndOfWorld("A message") from any of your handlers (tick, keyboard, mouse, etc.). If this method is used, you should override

WorldScene LastScene(string msg)

to return the appropriate final scene to display to the user of your game. The msg parameter is whatever string is passed to EndOfWorld. This approach is easier to use when deciding that the world has ended is cleanly split into each relevant handler.

1.3.5.2 ShouldWorldEnd🔗

For more isolated control, you can override

bool ShouldWorldEnd()

By default, this method always returns false, but you may override it to return true when you want the world to end. Once it does so, on the next tick, the background code will eventually call your LastScene method to get the final scene to draw.

Note: In this situation, the string parameter given to LastScene will probably be meaningless (since you aren’t directly calling the method yourself), so you should not rely on it.

Note: If the clock does not tick, then it is impossible to know when to call this ShouldWorldEnd method: instead, you must use the EndOfWorld approach above.

1.3.6 Funworld versus Impworld🔗

There are two variants of the World library supplied to you:

  • The Funworld library is a pure library, where every method produces a new WorldScene or World as needed. All event handlers return a World.

  • The Impworld library is an imperative library, using side effects to modify the existing WorldScene or World. All event handlers return void. WorldScene is also imperative, so the PlaceImageXY method modifies the existing scene, rather than creating a new one.

Be sure to use the version of the library requested by each assignment!
